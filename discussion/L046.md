# L046 · FULL · vlayer (Veridise, a763614) · V-VLYR-VUL-029 "Proofs may be replayed or frontrun" (Warning, Open)
## Pass 1: report only
Advisory: the Verifier's onlyVerified modifier accepts a proof without any replay key or caller binding. Apps that need unique proofs must add nullifiers; frontrunning lets someone else submit an observed proof first. Recommendation is documentation/best practice; no fix.
- C1 met. C2: effect is in apps built on vlayer, none named in the report. C3 met in mechanism: nothing in the base verifier fixes how often or by whom a proof is used.
- Analogous to L008 (library-level gap, consumer is the integrating app). But this one is more "here's a pitfall for app devs" than a hole in what the proof locks.
- Proposed: Y, P3 (replay; frontrun noted), C2 unclear, conf L–M. Pass 2: check onlyVerified and the repo's example apps to see if any real consumer is exposed.

- So nothing in the base verifier or the shipped apps is unbound. It's an app-developer best-practice warning.
