# L018 · FULL · Datachain LCP-zkDCAP (Quantstamp 2025-03, a0f3800) · DCAP-3 "Missing Strict Validation of Critical x.509 Certificate Extensions" (Low, Fixed 80cc77a)
## Pass 1: report only
The zkVM guest verifies Intel SGX DCAP quotes, including the PCK certificate chain up to the Intel root, but doesn't check Key Usage / Basic Constraints. A certificate wrongly marked CA:TRUE could sign further certs. Exploit needs such a cert to chain to the Intel root (which the client must also check is trusted).
- C1 met, C2 met (LCPClientZKDCAP registers enclave keys from the proof's output). C3: the outputs (enclave key, root cert hash, TCB status) are fixed by the proof; the gap is an in-guest validation rule, and only matters if Intel's CA issues a malformed cert.
- Guest-internal hardening. Proposed: N, NA, PSS N, conf H. No [circuit-soundness] tag: no practical forgery without CA compromise (hygiene, like L190).
