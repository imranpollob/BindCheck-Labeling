# L024 · FULL · Self (zkSecurity 2025-06, 4f18c75) · #01 "Defaulting to a zeroed config on unknown configId enables verification bypass" (High, acknowledged; fix fab8b3b)
## Pass 1: report only
The hub reads configId from userContextData (user/relayer-supplied) and looks up the owner-registered VerificationConfigV2. Unknown ids return the all-false struct, so OFAC, forbidden-country and age checks are all off. verificationConfigV2Exists is never called and is itself fooled by the all-zero config hash. Then the app's onVerificationSuccess runs.
- C1 met, C2 met (app callback grants access / acts), C3 met (which policy applies is chosen by the caller, not pinned by the app).
- Proposed: Y, P2 (policy ID not bound), PSS N, conf H. Similar to L042 (prover-picked verifier class).
