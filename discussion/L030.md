# L030 · FULL · vlayer (Veridise, a763614) · V-VLYR-VUL-002 "Missing DNS record validation allows email forgery" (Critical, Fixed PR 2079)
## Pass 1: report only
The email-proof code checks that the DNS record is notary-signed and that the DKIM signature verifies under its key, but never that the DNS record belongs to the email's From domain (or the DKIM d= domain). An attacker publishes a DKIM key on any domain they control, gets it notarised, and signs a forged email "from" any other domain. The proof then says "email from victim.com, verified".
- C1 met. C2 met: the prover contract's output (email from/to/subject/body) is acted on by the app's verifier contract. C3 met: who the email is from isn't fixed, because the key is not tied to the claimed domain.
- Same shape as L001 (SAMM: DKIM key not tied to the member's domain), which we labeled Y/P2.
- Proposed: Y, P2 (key/domain context not bound to the claimed identity), PSS N, conf M (one could also read it as an in-guest signature-check bug; it isn't "circuit-internal with no effect" because the consumer is told a forged sender).
