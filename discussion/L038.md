# L038 · FULL · Panther (Veridise Apr 2025) · V-PAN-VUL-004 "Nullifier verification can be disabled" (Critical, Fixed 69db60e)
## Pass 1: report only
ZSwapV1: `ForceEqualIfEnabled(zAccountUtxoInNullifier, hash(privKey, commitment)).enabled <== zAccountUtxoInSpendPrivKey`. Spend key 0 is a valid key, so the check is off and the nullifier can be any value; the same zAccount UTXO can be spent infinitely.
- C1 met, C2 met (contract marks the public nullifier spent and applies the tx). C3 met: the nullifier the consumer uses for replay protection is not fixed to the spent UTXO.
- GUIDE P3: "Nullifier or replay key not bound to the proof".
- Proposed: Y, P3, PSS N, conf H.

## Pass 2: code (panther-core 1e12ff2f50; fix 0082bcf41a)
- zSwapV1.circom L150 `zAccountUtxoInNullifier; // public`; L686 `enabled <== zAccountUtxoInSpendPrivKey`. PantherPoolV1 marks `isSpent[zAccountUtxoInNullifier] = true`, so the consumer's replay key is a public input the circuit doesn't pin to the spent UTXO when the key is 0.
- Fix 0082bcf: `enabled <== zAccountUtxoInNullifier`, so a nullifier of 0 would still disable the check, but PantherPoolV1.main requires `zAccountUtxoInNullifier > 0` (ERR_ZERO_ZACCOUNT_NULLIFIER), so it holds in practice. fix_addresses_flaw = Y (relies on the contract guard).
- Keep: Y, P3, H.
