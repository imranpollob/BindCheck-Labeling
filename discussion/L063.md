# L063 · LIGHT · Hinkal (Quantstamp 2023-10) · HNKL-1 "The Protocol Can Be Drained Through Commitment Duplication" (High, fixed ce73084 / 95bb18d / 7a13bf4)
The contract builds the verifier input array by concatenating circomData fields (tokenIds then inputNullifiers). Moving the nullifiers from inputNullifiers into tokenIds yields the identical array, so the proof verifies, but insertNullifiers() acts on the now-empty inputNullifiers: nothing is nullified, new commitments are inserted, and the old commitment can be spent again. Drains the pool.
- C1 met, C2 met (commitments inserted, nullifiers not marked), C3 met: which values the consumer treats as nullifiers isn't what the proof fixed.
- Consumer interprets the public-input array differently from the circuit. Proposed: Y, P5, PSS N, conf H.
