# L011 · FULL · Panther follow-up (Veridise, Sep 2025) · V-PAN-VUL-001 "Bypassing internal transfer limits via swaps" (High, Fixed PR#1 / 39b770d)
## Pass 1: report only
zSwap circuit checks internal transfer limits on utxoOutAmount * weight. For swap UTXOs the user sets the out amount to 0 because "the actual transferred value is appended later at the smart contract level", and the circuit lets swap UTXOs go to other recipients. So swap output to another user skips the limit.
- C1 met. C2 met (contract creates the swap output UTXO with the appended amount for the recipient). C3: the amount actually credited is set by the contract from the swap result, not by the proof; the proof's limit check ran on 0. "How much goes to another user" isn't fixed by the proved statement.
- Counter-view: the fix is circuit-side (force recipient = sender), so this could be read as circuit policy logic.
- Proposed: Y, P1, PSS N, conf M.

## Pass 2: code (panther-core 05e4b1cd9a; fix 81dae60f "enforce swap out-UTXO ownership and selective zone limits")
- zSwapV1.circom L553-556: swap UTXO hashed with `UtxoNoteHasher(isSwapUtxo)` and `utxoOutAmount === 0`; L620-623 limit check uses utxoOutAmount (0) * weight * isNotOwner, which always passes. Recipient (spend key) is free; isNotOwner just zeroes the check.
- SwapHandler.sol L59-75: contract executes the swap, gets outputAmount, then `zAssetUtxos[1] = outputAmountScaled.generateZAssetUtxoCommitment(inputs[ZSWAP_ZASSET_UTXO_OUT_COMMITMENT_2_PRIVATE_PART_IND])`. The credited amount is set on-chain, outside the proof, and attached to a proof-supplied partial commitment whose owner can be anyone.
- So the "how much goes to another user" value never passes through the proof's limit check. Fix 81dae60f restricts the swap UTXO owner to the sender.
- Keep: Y, P1, M (counter-view: by-design on-chain amount; bug could be read as circuit policy, like L012).
