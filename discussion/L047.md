# L047 · FULL · Self (zkSecurity 2025-06, 4f18c75) · #00 "An attacker can craft a fake non-inclusion proof for a given key due to an aliasing bug in the SMT verifier" (High, fixed 99e8eec)
## Pass 1: report only
The SMT non-inclusion circuit decomposes the key with Num2Bits(254), which aliases k and k+p for ~1/4 of keys; the prover walks a different path and "proves" a sanctioned key is absent. All OFAC checks use non-inclusion, so they're bypassed.
- C1 met, C2 met (OFAC flag consumed by the hub/app). C3: the SMT root is a public input the contract checks; the failure is an in-circuit decomposition under-constraint (private witness bits). The OFAC result bit the contract reads is a circuit output that is wrong because the circuit's rule fails.
- Same shape as L036/L012/L004 (circuit rule broken via private witness). Proposed: N, NA, PSS N, conf M.
