# L128 Aztec 2.0 (zk-bug-tracker #6): missing 32-bit check on note index makes nullifier non-deterministic
Source: reports/linked/zk-bug-tracker-56a9966-README.md (entry 6; Aztec disclosure). Nullifier derived from the note index, assumed 32-bit but unconstrained; any value with the right low 32 bits yields a different nullifier for the same note -> spend one note many times.
The nullifier is the replay key the contract records; it is not uniquely bound to the note. GUIDE P3 'nullifier ... not bound to the proof / aliasable'. Precedent L038/L105 (Panther in-circuit nullifier gaps labeled Y P3).
