# L066 · LIGHT · Linea contracts update (Diligence 2024-01) · 5.1 "Incorrect Final Block Number Can Be Finalized" (Critical, fixed PR-24)
finalizeCompressedBlocksWithProof sets currentL2BlockNumber = finalizationData.finalBlockNumber. When no new data is submitted, neither the contract nor the prover checks finalBlockNumber, so the operator can set the finalized block number wrongly and skip blocks. Fix: contract check + prover check + add finalBlockNumber/lastFinalizedBlockNumber to the PI.
- C1 met, C2 met (stores currentL2BlockNumber), C3 met (the stored block number isn't constrained by the proof).
- Proposed: Y, P1 (stored value effectively prover/operator-chosen), PSS N, conf M (operator trusted; labeled by mechanism).
