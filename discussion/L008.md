# L008 · FULL · SP1 Contract Call (Veridise, 6ccad76) · V-SP1CC-VUL-002 "Critical Anchor Consistency Checks Only Performed During Call Execution" (High, Fixed 804a19a)
## Pass 1: report only
Anchor resolution (checks that the execution block matches the referenced beacon block, then commits anchor id/hash to public values) only happens inside execute(). Log/metadata-only apps (e.g. the repo's events example) skip it: no public values about the block, no consistency checks. An attacker can prove arbitrary information about a block (e.g. correct state with a mismatched beacon root).
- C1 met. C2: a downstream consumer acting on proven logs/metadata (light clients, event-driven apps); library-level, so the effect is in the integrating app. C3 met: which block/chain the claim is about is not fixed by the proved statement.
- Proposed: Y, P2 (block/anchor context not bound), PSS N, conf M.
