# L006 · FULL · Zkopru (Least Authority 2021-06, 4236fc8) · Issue J "No Nullifier Uniqueness Check" (severity not given, Resolved)
## Pass 1: report only
The block generator (coordinator, TypeScript) doesn't check that a tx's nullifiers are unused before putting it in a block. A double-spend tx can land in a block; then the block is challengeable and the proposer is slashed (an attacker can even claim the slash reward), or the double spend survives if no one challenges. Team: client dry-run already ensures uniqueness.
- The rollup's own protection (fraud-proof challenge on duplicate nullifiers) exists; this missing check mainly hurts the proposer who skipped it. Off-chain component.
- Similar to "skipped consumer safety check" (L025, L002 → N). Proposed: N, NA, PSS N, conf M. Verify in code that the on-chain challenge covers used nullifiers.

## Pass 2: code (zkopru 4236fc8; fix 9f46d66 "check for nullifier uniqueness in block", Dec 2021)
- On-chain: NullifierTreeValidator.validateNullifierRollUp rebuilds the nullifier SMT with SMT254.fill, which requires non-inclusion ("Already existing leaf"), so a block reusing a nullifier is slashable. The protocol does enforce uniqueness.
- Fix is in coordinator block-generator.ts / layer2.ts (off-chain proposer self-check).
