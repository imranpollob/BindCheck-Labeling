# L014 · FULL · MorphL2 (Sherlock contest 207, 2024-09, e18890e) · H-2 "Attacker can freeze chain and steal challenge deposits using fake prevStateRoot" (High, fix 63a2543)
## Pass 1: report only
Rollup.commitBatch doesn't check that the batch's prevStateRoot equals the parent batch's postStateRoot; only finalizeBatch does. A malicious sequencer commits a batch with a valid transition from a fake prevStateRoot. When an honest challenger challenges, the sequencer proves that transition (valid proof) and wins: the challenger's deposit goes to the sequencer, no slash. The batch can't be finalized, so the chain halts.
- C1 met (proveState accepts the proof), C2 met (challenge resolved, deposit paid out, sequencer not slashed), C3 met: the proven transition's starting state isn't bound to the chain's actual previous state.
- Same shape as L166 / L048 / L149 (starting state not bound). Proposed: Y, P2, PSS N, conf H. Fix: check prevStateRoot in commitBatch.
