# L076 · LIGHT · SP1 Helios (OpenZeppelin diff audit, 6d554b9) · "Missing Check Potentially Allows Invalid Finality Updates" (client-reported, Resolved 31c682c)
## Pass 1: report only
SP1Helios.update checks `po.newHead > fromHead`, where `fromHead` is a function argument, but never checks fromHead == po.prevHead (the head the proof started from). With po.prevHead == po.newHead, the client skips updating finalized_header (so the execution payload is inconsistent) while the contract's check passes using a smaller caller-chosen fromHead. The store ends up with a header whose execution payload/state root is invalid.
- C1 met, C2 met (contract stores new head/state root/storage slot values on L2), C3 met: the starting state is a caller argument, not bound to the proof's prevHead.
- Proposed: Y, P2 (proof applied in a state context it wasn't made for), PSS N, conf M. Note: update is restricted to trusted updaters (Risk Labs); labeled by mechanism.

## Pass 2: code (across-protocol/sp1-helios 6d554b98; report fix 31c682c)
- SP1Helios.update(proof, publicValues, uint256 fromHead) onlyRole(UPDATER_ROLE): checks headers[fromHead] set, age, po.newHead > fromHead, sync committee for fromHead's period; verifies proof; then writes headers[po.newHead], executionStateRoots[po.newHead] (and storage slots). po.prevHead (and prevHeader) are never compared with fromHead / headers[fromHead]. Confirmed.
- Keep: Y, P2, M (trusted updater role mitigates; labeled by mechanism).
