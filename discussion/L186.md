# L186 Zellic Nori 3.6 [a3850] (High, L Medium): committed deposit root not constrained to be complete
Source: reports/linked/Nori Bridge - Zellic Audit Report.pdf (Zellic, 2026-07-24). Nori: Ethereum->Mina bridge; SP1 (Helios) proof converted by o1js verifier circuits (proof-conversion) and consumed by the Mina NoriTokenBridge zkApp, which authorizes nETH mints.
The SP1 guest proves inclusion of prover-chosen storage slots only; an empty or pruned deposit root is a valid proof. update is permissionless, so an attacker can front-run the operator with empty-root updates and keep everyone's mints out of the window (outage; funds recoverable later). The Mina contract stores a deposit root whose extent the prover chose.
GUIDE: extent case is OTHER; §3 exception: one party's valid proof blocking another party's state is binding.
Proposal: Y OTHER (extent), PSS N, M. Alt N (liveness only, funds not lost).
