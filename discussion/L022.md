# L022 · FULL · IBC Eureka (Zellic 2025-03, 6bb8fcf) · 3.1 "Untrusted input is used as trusted consensus state" (Critical, fixed 1f242e04; no fix_commit in sheet)
## Pass 1: report only
In the ethereum-light-client, verify_header builds a TrustedConsensusState from the stored consensus state plus a sync committee taken from the user's header, never checked against the stored committee (same for trusted_slot). An attacker supplies their own sync committee, signs a fake header, and updates the client with a wrong finalized/state root.
- Mechanism looks like "starting state not bound" (L149/L166). But this light client verifies BLS sync-committee signatures directly; the report mentions no ZK proof in this path.
- GUIDE §6 "Signature instead of proof": if the issue is purely signature verification with no ZK proof involved, C1 fails → N, unless the signature is checked inside a circuit or bound to a proof's statement.
- Proposed: N, NA, PSS N, conf M (check in code whether this light client runs inside a zkVM/SP1 program or natively in CosmWasm).
