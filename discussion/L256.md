# L256 zkSecurity OpenVM 2.0 #08 (Medium): unpinned public values length
Host verifier derives pv length from the prover-supplied vector; anyone can truncate (or extend with adjacent authenticated memory, usually zeros) the user public values of a valid proof and still verify. The accepted statement differs from the proved one: number of public values not fixed. Affects SDK verification (VmStarkProof, ContinuationVmProof), not stated for EVM.
Proposal: Y P4 (public-input length not pinned; alt P5), PSS N (integration input check), C2 unclear, L. Alt N (auditors call it malleability).
Revised before proposing: N, PSS N, L. Truncation only drops trailing true outputs (extension only adds already-authenticated memory, usually zeros); attacker cannot inject a false value, so every value the consumer does get is fixed by the proof. Alt: Y P4 C2 unclear if a consumer treats missing values as a meaningful default.
