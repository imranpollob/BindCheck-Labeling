# L001 · FULL · Oxorio SAMM · OpenZeppelin · "Unconstrained Domain in DKIM Signature" (High)

## Pass 1: report only (written before opening code)
System (report §System Overview): Safe module. Members approve a Safe tx by emailing msgHash as the subject; relayer builds a Noir proof per approval; SAMM contract verifies proofs and executes the allowlisted Safe tx when the threshold is met.
Finding: circuit checks the header signature against the given pubkey; contract checks pubkey hash is in the DKIM registry. "neither the circuit nor the contract ensures that the particular public key corresponds to the participant's email domain." A malicious DKIM signer can forge emails from members on other domains; also needs the member's secret (likely relayer collusion); "could significantly reduce the multisig threshold."

- C1 met: forged-approval proofs are accepted by the verifier.
- C2 met: SAMM executes the Safe transaction once approvals reach the threshold.
- C3 met: which DKIM key/domain authorizes a given member's approval is not fixed by the proved statement, so approvals count for members who never sent them (decides "who" approved).
- Proposed: binding=Y, pattern=P2 (domain/policy not bound to sender), PSS=N, confidence=M (P2 vs P1-identity is arguable; needs secret + rogue DKIM signer).

## Pass 2: code (samm-circuits 240b94a, samm-contracts c2d255d as named in the report; fix 6eb3eb9)
- Circuit public inputs at vuln: root, relayer, msg_hash; outputs (commitment, pubkeyHash). No domain anywhere in the circuit (builds/samm_2048/src/main.nr, lib/src/lib.nr verify_samm_logic).
- Contract SAMM.sol `_checkNProofs` (L459-491): `s_dkimRegistry.isDKIMPublicKeyHashValid(currentProof.domain, currentProof.pubkeyHash)`. `domain` is a caller-supplied field of `ISAMM.Proof` and is NOT written into pubSignals (only [170]=commit, [171]=pubkeyHash). The consumer makes its policy decision on a value the proof never sees, which is exactly C3.
- Fix 6eb3eb9 (commit e01bae7 "fix: OZ_L-04, OZ_H-01"): adds `domain: pub BoundedVec<u8, 24>` and asserts `padded_member[member_seq.length - domain.len + i] == domain.storage[i]`, so domain is a suffix of the member's address.
- Fix gap: it is a plain suffix match with no check for '@' before the domain. Member `alice@notevil.com` matches domain `evil.com`, so whoever controls a registered DKIM key for evil.com can still forge alice's approvals. Fix is partial (the report also says OZ did not review it). Matters for the "fixed version = negative" evaluation.
- Confirms Pass 1: binding=Y, pattern=P2. Confidence up to H for binding.
