# L016 · FULL · PrivacyBoost (OpenZeppelin 2026-04, 7b2a018) · "Low-Order BabyJubJub Keys Enable EdDSA Forgery" (Medium, Resolved PR #238: 784a19b, a79ed6e, 6643a5b)
## Pass 1: report only
The gnark EdDSA verifier clears the cofactor on the public key (A8 = 8A) but doesn't check A is in the prime-order subgroup. A low-order key (even the identity) makes A8 = O, so S*B8 = R8 holds for any message: signatures forgeable without the secret key. Fix: reject low-order keys at registration/rotation.
- Who registers the key? The account owner (AuthRegistry). So a forgeable account is one whose owner registered a degenerate key. No consumer-read value is unlocked: auth roots, nullifiers, commitments are all fixed by the proof; the weakness is the in-circuit signature check for degenerate keys.
- Proposed: N, NA, PSS N, conf M, tag [circuit-soundness]. Check in code whether anyone other than the owner can set an account's key.
