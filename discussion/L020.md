# L020 · FULL · Anon Aadhaar (PSE 2024-03, c4ef018) · H1 "User can bypass nullifier by changing photo" (High, no fix: "no way to avoid")
## Pass 1: report only
The nullifier is computed over signed Aadhaar data that includes the photo. A user who updates their photo gets a freshly signed QR and so a new nullifier, and can act twice (e.g. vote before and after the change). Signed data has no photo-update timestamp, so it can't be detected; abuse limited by how often photos can change.
- C1 met, C2 met (app marks nullifier used / counts vote). C3: the nullifier the consumer uses for "once per person" isn't fixed to the person; the same identity can yield several valid nullifiers.
- Not a circuit soundness bug: the circuit computes what it was designed to, on honestly signed data. It's the replay key's scope.
- Proposed: Y, P3 (nullifier not bound to the identity it's meant to limit), PSS N, conf M. Arguable N: needs a legitimate re-issue by UIDAI, and the data is genuine.

## Pass 2: code (anon-aadhaar c4ef018; no fix_commit)
- helpers/nullifier.circom: nullifier = Poseidon(nullifierSeed, Poseidon(photo[0:16]), Poseidon(photo[16:32])). Photo only; no stable identifier (e.g. Aadhaar number hash).
- Example consumer AnonAadhaarVote.voteForProposal: require(!hasVoted[nullifier]); hasVoted[nullifier] = true. So a re-issued QR with a new photo votes again. Confirmed.
