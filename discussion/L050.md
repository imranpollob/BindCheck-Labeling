# L050 · FULL · vlayer (Veridise, a763614) · V-VLYR-VUL-001 "Missing EVM environment validation allows proof spoofing" (Critical, Fixed PR 1891/1950)
## Pass 1: report only
The call guest's public outputs give the start block number and hash, call target, selector and return value, but not the chain ID. The prover supplies the chain ID, which picks the ChainSpec (EVM rules, and whether teleport checks are skipped for a "local testnet"). An attacker keeps the expected block number and hash but swaps the chain ID: wrong EVM semantics, or teleport verification skipped, so the target-chain state is attacker-controlled. Fix: chain ID goes into CallAssumptions and the on-chain ProofVerifierBase checks it against the executing chain.
- C1 met. C2 met: the on-chain verifier/consumer acts on the call result. C3 met: which chain/config the execution ran under isn't fixed by the public outputs.
- Proposed: Y, P2 (chain ID / config context not bound), PSS N, conf H.
